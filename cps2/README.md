# CPS-2 サウンドROMからMIDIへの変換

この変換ツールは、ゲームごとのXMLファイルからCPS-2のコードROMと曲名を
読み込み、Standard MIDI Format 0のファイルを生成します。曲ごとの出力は単一トラックに
まとめますが、各パートのMIDIチャンネルとイベント、テンポ情報は保持します。

- ROMファイル: `roms/<archive>/`
- ゲーム情報XML: `games/`
- 生成するMIDIファイル: `midi/<archive>/`
- 生成するQSoundサンプルWAV: `wav/<archive>/`

## 使い方

ワークスペースのルートフォルダーから、Python 3で次のように実行します。

```powershell
python .\cps2\convert_to_midi.py .\cps2\games\xmcota.xml
```

出力先は `cps2/midi/<archive>/` です。出力先を変更する場合は
`--output-dir` を指定します。

```powershell
python .\cps2\convert_to_midi.py .\cps2\games\xmcota.xml --output-dir .\exports\xmcota
```

既定ではシーケンスに記録されたノート番号をそのまま出力し、`unity_key`による
移調は行いません。必要な場合だけ `--unity-key-reference` を指定すると、
サンプルの `unity_key` が指定したMIDIノート番号になるよう楽器ごとに移調します。

```powershell
python .\cps2\convert_to_midi.py .\cps2\games\ssf2t.xml --unity-key-reference 60
```

## XMLとROMの配置

XMLの `<romlist>` には `archive` 属性を指定し、ROMごとに `type`、`offset`、
ファイル名を記述します。`type="code"` のROMは
`cps2/roms/<archive>/` から読み込まれ、指定されたオフセットに配置して
コードROMイメージを構成します。`type="pcm"` のROMも同じフォルダーから読み込み、
QSoundサンプルのWAV出力に使用します。`<romlist>` には音源メタデータとして
`instrument-table`、`instrument-banks`、`sample-table`、
`sample-table-length` も指定します。これらはコードROM内の楽器表とサンプル情報表の
位置・サイズです。通常の連続した楽器表は既定の形式で読み込みます。
別バンクへのポインターを持つ形式では、`instrument-table-format="pointers"` を指定します。

## QSoundサンプルWAV

変換時に、楽器表から参照されるユニークなサンプルを
`cps2/wav/<archive>/<sample番号>.wav` に出力します。同じサンプルを使う複数の楽器は
同じWAVを共有します。`instruments.csv` にはMIDIのバンク・プログラム番号、
サンプル番号、`unity_key`、WAV名の対応を記録します。

WAVはモノラル、16-bit PCM、24,038 Hzです。CPS-2のPCM ROM配置に合わせた
16-bitワードスワップを行い、サンプル情報表の開始・終了位置から波形を抽出します。
このWAV出力は波形データの抽出であり、QSoundのループ位置や音量エンベロープは
WAVに反映しません。サンプル表の範囲外を指す楽器番号は、QSoundの既知の解析動作に
合わせてサンプル0へ割り当てます。XMLに楽器表・サンプル表のメタデータがない場合は
抽出を明示的にスキップします。対応するROMとテーブル情報のあるX-Men: Children of
the Atom、Super Street Fighter II Turbo、Vampire Saviorを収録しています。

`<titlelist>` には、変換する各曲のシーケンスコードと表示名を記述します。
[xmcota.xml](./games/xmcota.xml) はXMLの記述例です。

## 変換内容と制限

MIDIの分解能は48 PPQN、ノートオンのベロシティは127です。テンポ、プログラム
チェンジ、チャンネルボリューム、パンは、MIDIで表現できる範囲で出力します。
CPS-2の符号付きピッチベンドはMIDIピッチホイールに変換します。また、
ポルタメントレートはタイでつながる音符間の連続的なピッチホイール変化として
出力します。ビブラートの深さとLFOレートにはCPS-2共通の参照テーブルを使い、
ドライバーの更新周期である62.5 Hzで三角波LFOを計算してピッチホイールイベントに
変換します。深さ・レートの両テーブルはコマンド値0～127の全128項目を収録して
います。

`unity_key`による移調は既定では無効です。`--unity-key-reference MIDI_NOTE`を
指定した場合、各楽器が参照するサンプルの基準音がそのMIDIノートになるよう、
`MIDI_NOTE - unity_key`半音だけ移調します。これは音域・調性を変える正規化であり、
ゲーム本来の絶対音程を復元する処理ではありません。音源や目的に合う根拠がない場合は、
オプションを付けずシーケンスのノート番号を使ってください。

ピッチ変化を使うトラックでは、MIDIピッチベンドの範囲を上下18半音に設定します。
ROM解析で確認したタイ音符間の最大音程差は1オクターブで、ピッチベンドと
ビブラートの同時適用に備えた余裕があります。MIDIのピッチベンドはチャンネル
単位で適用されます。

通常のノートゲート長は `delta * gate / 256`（`gate` は8ビット値）で、
次のデルタ時間までに終了するため、通常の音符は重なりません。明示的なタイが
レガートに相当し、つながった音符は1つのMIDIノートオン／ノートオフで保持し、
ピッチホイールで音程を移動します。生成したトラックでは、各MIDIチャンネルで
同時に発音するノートが最大1つであることを確認しています。ゲート長が0の音符は、
同じティックでノートオンの直後にノートオフを出力します。

LFOは62.5 Hzのドライバーフレームごとに更新されます。ROMの増分テーブルと
上限テーブルに基づく三角波は、深さの上限で折り返します。そのため、実際の周期は
連続値による近似式 `4 * 65536 / lfo_rate_units` とわずかに異なる場合があります。
例えば、レートインデックス90（`0x32B0`）の測定周期は22フレーム（2.84 Hz）、
インデックス120（`0xBCC4`）は6フレーム（10.42 Hz）です。深さインデックス30
（`0x2D` 単位。`0x100` が1半音）は、±0.175781半音（±17.58セント）です。
MIDI出力との差は14ビットのピッチホイール量子化の範囲内です。ROMで使われる
深さインデックスは最大100（±3.90625半音）です。MIDIイベントは、各シーケンスの
テンポに基づき、対応するドライバーフレームの時刻に配置されます。

この初期版では、ゲームごとのROM配置と曲情報をXMLで指定できますが、シーケンス
解析はCPS-2 V1.05の音楽ドライバーと既知のコマンドテーブルを対象としています。
MIDIには解析した音符・制御イベントを出力します。抽出したQSound WAVは個別の
サンプルファイルであり、MIDI音色として自動的に組み立てる処理やCPS-2の
楽器エンベロープ再現は行いません。そのため、MIDIの再生にはMIDIプレーヤー側の
音源が使われ、ゲーム本来のQSound音色とは異なります。
