# CPS-1 サウンドROM 仕様 (v2.00 / v3.50 / v4.25)

特に**シーケンスデータ**のバイトレベル解析をまとめたドキュメントです。
VGMTrans (`src/main/formats/CPS/CPS1Scanner.cpp`) と MAME のソースを突き合わせ、
実ROMで検証した結果を基に作成しています。

## 1. レイアウト全体

CPS-1 のサウンドプログラムは**コードROM** (Z80実行可能なサウンドドライバ+データ) と
**PCM ROM** (MSM6295波形) に分かれます。コードROM内の主要データは
アドレスが**低めの領域** (0x1000付近〜) に集中しています。

```
コードROM (64KB = 0x10000)
┌─────────────────────────────────────────────┐ 0x0000
│ Z80 サウンドドライバ (コード)                 │
│ ...                                         │
├─────────────────────────────────────────────┤ 0x1000 付近
│ ★ テーブルヘッダ  (count / masterVol / ptr)  │
│   └─ OPM 音色テーブル (127 record)           │
│   └─ [V4.25:] PCM音色テーブル                │
│   └─ シーケンステーブル (count × BE16 ptr)    │
│   └─ シーケンス本体 (各: flag + 12×BE16)      │
│   └─ トラック本体 (opcode バイト列)          │
├─────────────────────────────────────────────┤
│ 0xFF パディング (未使用領域)                  │
└─────────────────────────────────────────────┘ 0x10000
```

> **重要:** テーブルは `format-version` で決まる固定ヘッダを持つ**1つの位置**にあり、
> その位置は ROM 自体からは一意に判定できない (同じ構造を持つ偽のテーブルが
> 複数存在する)。そのため ROM からの自動検出は行わず (2025-10 に削除)、
> 同梱の `tables.json`（VGMTrans の `mame_roms.json` を転記した CPS-1
> ゲーム別テーブル）から、**コードROMのファイル名 → MAME名 (`archive`)
> の順**で解決します。XML の `<romlist>` には `archive` と `<rom>` 要素のみで
> 十分です。

## 2. テーブルヘッダ (バージョン別)

`tables` オフセットからのヘッダ構成はバージョンで異なります
(VGMTrans `CPS1Scanner.cpp` の `case` 分岐と一致)。

### CPS1_V2.00 (3バイトヘッダ)

| オフセット | バイト | 内容 |
|:---------:|:------:|:-----|
| `+0` | 1 | `numSeqs` (使用シーケンス数) |
| `+1` | 2 (BE16) | **OPM 音色テーブル** ポインタ |
| `+3` | … | シーケンステーブル (次節) |

- OPM レコードサイズ: **32 バイト** (V3.50以降より短い)
- masterVol: 固定 `0x7F` (ヘッダに格納されない)
- PCM 音色テーブル: **なし** (program N は sample N-1 を直接選択)

### CPS1_V3.50 (4バイトヘッダ)

| オフセット | バイト | 内容 |
|:---------:|:------:|:-----|
| `+0` | 1 | `numSeqs` |
| `+1` | 1 | `masterVol` |
| `+2` | 2 (BE16) | **OPM 音色テーブル** ポインタ |
| `+4` | … | シーケンステーブル |

- OPM レコードサイズ: **40 バイト** (`CPS1_FM_INSTRUMENT_SIZE`)
- PCM 音色テーブル: なし (program = sample-1 の恒等マッピング)

### CPS1_V4.25 (6バイトヘッダ)

| オフセット | バイト | 内容 |
|:---------:|:------:|:-----|
| `+0` | 1 | `numSeqs` |
| `+1` | 1 | `masterVol` |
| `+2` | 2 (BE16) | **OPM 音色テーブル** ポインタ |
| `+4` | 2 (BE16) | **PCM 音色テーブル** ポインタ |
| `+6` | … | シーケンステーブル |

- OPM / PCM レコードサイズ: 40 バイト
- OPM テーブル長は `min(127 × 40, sample_instr_table_offset)`

> `numSeqs` は**最高コードではなく使用スロット数**。例: Final Fight は
> code `0xF0` まで使っているのに `numSeqs = 0xC3`。したがってシーケンステーブルの
> サイズは `numSeqs` ではなく**必要とする最高コード**で決める
> (`min(256, max(titles)+1)`)。

## 3. 対応ゲームと tables オフセット

| ゲーム | 実フォーマット | `tables` | 備考 |
|:------|:-------------:|:--------:|:-----|
| ffight   | CPS1_V2.00 | `0x1000` | 当初 `0x0704` が誤検出値 |
| 1941     | CPS1_V2.00 | `0x1000` | 当初 `0x06ee` が誤検出値 |
| mercs    | **CPS1_V3.50** | `0x1000` | XML は当初 V2.00 と誤記載。実体は V3.50 |
| msword   | CPS1_V3.50 | `0x1000` | V3.50 形式で唯一整合するヘッダ |
| knights  | CPS1_V4.25 | `0x1100` | V4.25 形式で唯一整合するヘッダ |
| sf2ce    | CPS1_V4.25 | `0x1100` | |

### オフセットの一意性を判別した方法

`tables` の位置は ROM から一意には決まらないため、各候補オフセットの
**生ヘッダ**を比較して確定しました。真のテーブルは次を満たします:

- `numSeqs` が妥当な値 (1〜255)
- OPM ポインタが ROM 内・パディング外
- シーケンステーブルのポインタ列が**単調増加**している

実測例 (msword, V3.50):

```
0x1000: cnt=0x57  opm=0x10b2  seq=[0x20b2 0x23fb 0x257f 0x2e86 0x36c0 0x4128]  ← 単調増加 ✓ 真
0x0fae: cnt=0xc0  opm=0x0408  seq=[0x1020 0x4080 0x9    0x1224 0x4890 0x0]      ← 乱れ ✗ 偽
0x4018: cnt=0x08  opm=0x8a08  seq=[0x2991 0x6a08 0x2a74 ...]                     ← cnt過小 ✗ 偽
```

実測例 (knights, V4.25):

```
0x1100: cnt=0x75  opm=0x11f0  sample=0x21f0  seq=[0x2328 0x28c2 0x2d94 ...]      ← 単調増加 ✓ 真
0x1120: cnt=0x65  opm=0x6757  sample=0x6862  seq=[0x696d 0x6b5a 0x6eae 0x7019 ...] ← 連続すぎる ✗
0x4354: cnt=0x01  opm=0x3803  sample=0x6f08  seq=[0x2 0x381 ...]                 ← cnt過小 ✗ 偽
```

> **教訓:** `format-version` が ROM の実態と食い違うと (mercs が V2.00 表記なのに
> 実際 V3.50) ヘッダ解釈自体が崩れ、テーブル自体を見つけられない。
> 現在は `tables.json` に `format-version` と `tables` をセットで保持し、
> XML から ROM名・`archive` でのみ解決するため、この種の食い違いは
> テーブル側が正しい値を保証する (vgmtrans / ROM 実測で裏取り済み)。

## 4. シーケンステーブル

`tables + header_size` 以降に **`numSeqs` 個の BE16 ポインタ**が並び、
各曲コード (0x00〜0xFF) のシーケンス先頭を指します。

```
シーケンステーブル (address = tables + header_size)
┌────────────┬────────────┬─────┬────────────┐
│ code 0x00  │ code 0x01  │ ... │ code 0xFF  │
│ BE16 ptr   │ BE16 ptr   │     │ BE16 ptr   │
└────────────┴────────────┴─────┴────────────┘
```

- ポインタ = `0` の場合: そのコードは未使用 / サンプル再生項目 (スキップ)
- ポインタ先頭の **bit7 (0x80) が立っている場合**: サンプル単発再生
  (PCM one-shot)。シーケンスとして扱わずスキップする
  (`if start & 0x80: continue`)
- 有効なシーケンス: 先頭1バイト (bit7=0) + 12×BE16 のトラックポインタ

> 各バージョンでシーケンステーブルの先頭はヘッダ直後ですが、
> OPM 音色テーブルとシーケンステーブルの**順序は逆**に並ぶ
> (OPM が先、シーケンスが後) ゲームもあります。本変換器はヘッダの
> ポインタを信用するため順序に依存しません。

---

## 5. シーケンスヘッダ

各曲コードが指すシーケンス先頭 (`start`) の構造:

```
オフセット  内容
─────────────────────────────────────────
start +0    flag バイト  (bit7=0 ならシーケンス / bit7=1 なら PCM one-shot)
start +1    トラック1 のポインタ  (BE16)
start +3    トラック2 のポインタ  (BE16)
  ...
start +23   トラック12 のポインタ (BE16)
```

- **最大12トラック** (`decode_sequence` は `range(12)`)
- トラック8〜12 (index 8〜11) は **PCM (MSM6295) チャネル**
  - MIDI チャンネル 10 に統合出力
  - index 0〜7 は YM2151 (MIDI チャンネル 1〜8)
- ポインタ = `0` のトラックはスキップ
- **12トラック全て 0** の場合は**プレースホルダ**とみなし空シーケンス扱い
  (例: Final Fight BGM 3, code 0x42)
- ポインタが `0xFF` パディング内を指すトラックはスキップ
  (16バイト連続 0xFF 判定)

> **注意:** トラックデータはシーケンスヘッダより**低いアドレス**に存在してよい。
> したがってトラックポインタの妥当性は「0 以外」「ROM 範囲内」しかチェックしない。
> (`pointer < start` は不正ではない)

## 6. トラックデータとオPCODE

トラックは 1 バイト単位の opcode バイト列。`decode_track` は
`MAX_STEPS` (200000) 回までデコードループを回します。

### opcode の判定 (status = data[pos])

```
status >= 0x20 ──────────→ ノート/イベント系 (下位5ビット + bit4 が意味を持つ)
status == 0x00..0x1F ────→ 制御系ステート命令 (下記テーブル)
```

### ノート/イベント系 (`status >= 0x20`)

`status` の分解:

| ビット | 意味 |
|:------:|:-----|
| `bit7..5` (>>5 &7) | `selector` (0〜6)。7 以上は不正 → トラック終了 |
| `bit4` (0x10) | ノート/非ノートの切り替え (ノートステート機械) |
| `bit3..0` (& 0x1F) | 非ゼロならノートデータ (音階)。0 ならタイミングのみ |

**タイミング delta の選択** (ノートステート機械 `note_state` に依存):

```
selector = ((status >> 5) & 7) - 1
if note_state & 0x30 == 0:          table = 1
elif note_state & 0x10 == 0:        table = 0
else:  note_state &= ~0x10          table = 2
delta = DELTA_TABLE[table][selector]
```

`DELTA_TABLE` (インデックス = 上の `table` 変数):

```
table 0: ( 2,  4,  8, 16, 32,  64, 128)
table 1: ( 3,  6, 12, 24, 48,  96, 192)
table 2: ( 0,  9, 18, 36, 72, 144,   0)
```

**ノートデータあり** (`status & 0x1F` 非ゼロ) の場合:
- PCM チャネル (track_index >= 8): 音階は `sample_program` に対応する
  デコード済み PCM サンプルのノート番号
- YM2151 チャネル:
  ```
  key = (status & 0x1F) + OCTAVE_TABLE[note_state & 0x0F] + 11
        + transpose + global_transpose      # 0..127 にクランプ
  ```
- 長さ: `duration = delta * note_duration >> 8`
- **タイ** (`note_state & 0x40` かつ非 PCM): ノートオフを発しないまま
  音程をピッチベンドで滑らかに変化させ、保持音符を継続

`OCTAVE_TABLE` (オクターブオフセット、半音):

```
(0, 12, 24, 36, 48, 60, 72, 84, 24, 36, 48, 60, 72, 84, 96, 108)
```
(下位4ビットで 0..15。0x00〜0x07 と 0x08〜0x0F でオクターブが変わる)

#### タイ (0x40) の終了 — ノートの連続と再トリガ

タイ中の音程はピッチベンド (CC0/E0) で滑らかに変化させ、保持音符は
そのまま継続する。**タイが切れた (0x40 がクリアされた) 瞬間**の挙動は
終端ピッチと開始音程 (`held_note`) の関係で決まる (VGMTrans
`CPS1TrackV2.cpp` と一致):

```
タイ終了時:
  key == held_note  → 再トリガしない。保持中の音符の OFF を
                      当該ノート長さ分後ろに延ばすだけ
                      (VGMTrans: addTime(absDur) + NoteOff)
  key != held_note  → OFF(旧) を発したうえで ON(key) を再トリガ
```

> **注意:** タイ終了でも音程が同じ場合 (例: `0x91` → `0x8f` のような
> 同音程の連続) は**同一音符として扱い続ける**必要があり、OFF+ON で
> 再トリガすると YM2151 エンベロープがリセットされ音が途切れる。
> これが Final Fight BGM 1 トラック 1 の「3・4 ノート目の音が分かれる」
> 不具合の正体だった (2026-10 に修正)。

### 制御系ステート命令 (`0x00`〜`0x1F`)

| opcode | 内容 |
|:------:|:-----|
| `0x00` | `note_state ^= 0x20` (デルタテーブル選択用フラグ反転) |
| `0x01` | `note_state ^= 0x40` (タイフラグ反転) |
| `0x02` | `note_state |= 0x10` |
| `0x03` | `note_state ^= 8` |
| `0x04` | `note_state = (note_state & 0x97) \| data[pos]` (オクターブ指定) |
| `0x05` | **テンポ**: `BE16 ticks_per_iteration` (次節) |
| `0x06` | `note_duration = data[pos]` (ノート長さ係数) |
| `0x07` | 音量 (PCM は減衰テーブル経由) |
| `0x08` | プログラム / サンプル選択 (`value % 128`) |
| `0x09` | `note_state = (note_state & 0xF8) \| value` |
| `0x0A` | **グローバル移調** `signed_byte(value)` |
| `0x0B` | **ローカル移調** `signed_byte(value)` |
| `0x0C` | **ピッチベンド** `value >> 2` (半音換算 + 符号) |
| `0x0D` | (未使用 / 無視) |
| `0x0E`〜`0x11` | **有限ループ** (loop 0〜3) → [§8](#8-ループ系opcode-の詳細) |
| `0x12`〜`0x15` | **ループ終了 + 飛躍** (loop 0〜3) → [§8](#8-ループ系opcode-の詳細) |
| `0x16` | **無限ループ** (再入時は停止。`forever_offsets` 管理) |
| `0x17` | **トラック終了** (`break`) |
| `0x18` | **パン** `data[pos] * 4` (CC10, max 127) |
| `0x19`〜`0x23` | パラメータ1バイトを消費して無視 (未定義) |
| その他 | **未知 opcode** → VGMTrans と同様にトラックを停止 |

#### テンポ (`0x05`) の換算

```
tempo_ticks_per_iteration = BE16
micros_per_beat = ((PPQN << 8) / ticks_per_iteration) / 62.5 * 1_000_000
# PPQN = 48
```

`micros_per_beat` は `1..0xFFFFFF` にクランプして MIDI メタテンポとして出力。

#### 移調とピッチベンドの合成

- `global_transpose` (0x0A) と `transpose` (0x0B) は半音単位で加算
- `pitch_bend` (0x0C) は 0..63 → 0..100% へ換算し、符号付き半音として
  ピッチベンド CC (E0) で出力
- タイ中の音程変化は**ピッチベンド**で表現 (ノートオンの再送信ではない)

## 7. ノートステート機械と音程決定

`note_state` は 8 ビットのフラグ群。ビットの役割:

| ビット | 意味 | 設定/操作 |
|:------:|:-----|:---------|
| `0x40` | **タイフラグ** (ノートオフを発さないで音程を変える) | 0x01 で反転 |
| `0x20` | デルタテーブル選択 (table 1/0 の切り分け) | 0x00 で反転 |
| `0x10` | デルタテーブル選択 (table 2 の切り分け) | 0x02 で設定 |
| `0x08` | 未使用フラグ | 0x03 で反転 |
| `0x0F` | **オクターブ** (OCTAVE_TABLE のインデックス) | 0x04 / 0x09 で設定 |

**delta テーブルの選択ロジック:**

```
if note_state & 0x30 == 0:      # 0x20 と 0x10 の両方が0
    table = 1                    # (3,6,12,24,48,96,192)
elif note_state & 0x10 == 0:    # 0x20 があるが 0x10 がない
    table = 0                    # (2,4,8,16,32,64,128)
else:                            # 0x10 がある
    note_state &= ~0x10          # 0x10 をクリアして次回以降 table 0/1
    table = 2                    # (0,9,18,36,72,144,0)
```

つまり `0x10` は「1回だけ table 2 を使って、次に戻す」一次性フラグ。
これが CPS-1 の複雑なタイミング表現 (トリル / 連符) を可能にしている。

## 8. ループ系オPCODE の詳細

### 有限ループ (`0x0E`〜`0x11`, loop 0〜3)

```
opcode = 0x0E + loop_num
パラメータ: [count: 1B][jump_target: BE16]
```

`decode_track` の状態: `loops[4]`, `loop_offsets[4]` (各ループ独立)。

分岐ロジック:

```
if loops[loop_num] == 0 and loop_offsets[loop_num] == 0:
    # 初回到達: ループを開始
    loop_offsets[loop_num] = pos        # (count の後 = jump の位置)
    loops[loop_num] = data[pos]
    pos += 1
elif loop_offsets[loop_num] != pos:
    # リシンズレ (不正な再入) → VGMTrans と同様にトラックを停止
    break
else:
    # ループの繰り返し: count 減算
    loops[loop_num] -= 1
    pos += 1
# 続いて jump_target を読んで飛躍
jump = BE16(data[pos]); pos += 2
if not jump: break
if loops[loop_num] == 0: loop_offsets[loop_num] = 0
else:                    pos = jump
```

> **注意:** ループ開始時は `count` を読み、以降は `count` を読み飛ばして
> (pos+1) で `jump_target` を読む。初回と反復で消費するバイト数が異なる点に注意。

### ループ終了 + 飛躍 (`0x12`〜`0x15`, loop 0〜3)

```
opcode = 0x12 + loop_num
パラメータ: [note_state: 1B][jump_target: BE16]
```

```
if loops[loop_num] - 1 == 0:
    # ループ回数が切れた: 出口として jump_target へ飛躍
    loops[loop_num] = 0
    loop_offsets[loop_num] = 0
    note_state = (note_state & 0x97) | data[pos]   # オクターブ設定
    pos += 1
    pos = BE16(data[pos])
else:
    # 未到達: 3バイトスキップして進行
    pos += 3
```

これは「有限ループが count 回消化された後の**出口先**」へのジャンプ。
CPS-1 の「イントロ→ループ×N→アウトロ」構造を実現する。

### 無限ループ (`0x16`)

```
パラメータ: [jump_target: BE16]
```

```
if command_offset in forever_offsets: break   # 2回目の再入で停止
forever_offsets.add(command_offset)
pos = BE16(data[pos])
if pos == 0: break
```

無限ループは**1周だけ**展開して停止 (VGMTrans と同じ挙動)。

## 9. PCM / MSM6295

### サンプルテーブル (PCM ROM 先頭)

PCM ROM の先頭 1KB までに 8 バイト×N 個のサンプルエントリ:

```
エントリ (8B):
[0..3]  start (>>8)   BE24相当 (上1バイト無視)
[3..7]  end   (>>8)
```

- 8バイト連続 `0xFF` で終了
- サンプル番号 = `offset // 8 - 1` (0始まり)

### MSM6295 ADPCM デコード (`decode_msm6295`)

49 値の `step_table` と `index_shift` テーブルによる差分符号化。
16-bit モノラル PCM (<<4 シフト) で `7576 Hz` として WAV 出力。

### サンプル → MIDIノート

```
PCM_NOTE_BASE = 24
note = 24 + (サンプル番号のソート済みインデックス)
```

- MIDI チャンネル 10 で統合出力
- program N → sample N-1 (V2.00/V3.50 は恒等マッピング)
- V4.25 は PCM 音色テーブル (8B×N, `[0x80+flag, sample_index-1, ...]`) でマップ

### PCM チャネルの音量 (`0x07`)

```
attenuation = (32,22,16,11,8,6,4,3,2,0,...)[(8 - value) & 0x0F]
volume = round(127 * attenuation / 32)
```

## 10. 実データで確認したエッジケース

### 10.1 `0xFF` パディングを指すトラック

Final Fight の「Phone 2」(code 0x44?) トラック0が `0x9108` を指すが、
実データは `0x07FF` で終わる。`0x9108` は 0xFF パディング内。
そのままデコードすると数MBの誤ったノートオンが生成される。
**対策:** トラックポインタ先頭の 16 バイトが全て `0xFF` ならスキップ。

### 10.2 プレースホルダシーケンス

全12トラックが 0 のシーケンス (例: Final Fight BGM 3, code 0x42)。
VGMTrans と同様に「空シーケンス」として扱い、警告だけ出してスキップ。

### 10.3 サンプル単発再生 (bit7=1)

シーケンステーブルのポインタ先頭が `0x80` 以上の項目は PCM one-shot。
MIDI 化せずスキップ (例: ボイス、効果音)。

### 10.4 未知 opcode / ループ再シンズレ

不明 opcode やループの不正な再入は、VGMTrans と同じく**そのトラックを停止**
(後続のトラックはデコード継続)。

### 10.5 `format-version` の誤記載 (mercs)

mercs は XML に `CPS1_V2.00` と記載されていたが、ROM の実体は **V3.50**
(4バイトヘッダ, tables=0x1000)。V2.00 の3バイトヘッダで解釈すると
OPM ポインタが内容範囲外を指し、全タイトルが失敗した。
`format-version` と `tables` を ROM 実態に合わせ修正して解決。

### 10.6 自動検出の削除と tables.json

`tables` の ROM 内自動検出 (`autodetect_tables_candidates`) は
- 偽テーブル (上記 §3 のように構造だけ似る位置) を誤って採用しうる
- `format-version` が誤ると検出自体が崩壊する

ため **2025-10 に削除**。その代替として `cps1/tables.json` を用意しました。
これは VGMTrans の `mame_roms.json`（CPS-1 の各ゲームがどの `tables` と
どの `format-version` を使うかの既知のテーブル）を転記したもので、
XML の `<romlist>` から **コードROMのファイル名 → MAME 名 (`archive`)
の順**で解決します。`tables.json` に該当ゲームが無い場合は
`archive ... not matched in tables.json` のエラーになります。
